# اختبارات القرآن الكريم

موقع عربي متجاوب لعرض **1425 نموذج اختبار شفوي** للقرآن الكريم، مع معاينة الأسئلة، وتعديل مركزي عبر Supabase، وطباعة وتنزيل Word وZIP محدثين من داخل المتصفح.

## النظامان المعتمدان

- **النظام السفلي:** 27 وحدة مسماة تبدأ من «الناس» وتصعد إلى أعلى المصحف. يحتوي كل اختبار على 25 نموذجًا، أي 675 نموذجًا. أسماء الوحدات مثل: «الأعراف»، «الأنفال إلى التوبة»، «باقي البقرة».
- **النظام العلوي:** 30 نطاقًا قياسيًا من أعلى المصحف إلى أسفله. يحتوي كل اختبار على 25 نموذجًا، أي 750 نموذجًا.

الإجمالي: **57 اختبارًا × 25 نموذجًا = 1425 نموذجًا**.

## قواعد توليد الأسئلة

- لا توجد أسئلة من سورة الفاتحة، ولا تبدأ الأسئلة من الآية الأولى أو الثانية من أي سورة.
- بداية كل سؤال من موضع قرآني موثق، ونهايته عند خاتمة آية فعلية، ويُعرض السؤال بصيغة «من قوله تعالى ... إلى ختام الآية ...».
- الأسئلة الأساسية موزعة على أول 7 أوجه، وثاني 7 أوجه، وآخر 6 أوجه من الوحدة أو الجزء. السؤال الاحتياطي يوضع بين السؤال الأول والثاني أو بين الثاني والثالث.
- يوجد فرق لا يقل عن 3 أوجه بين بدايات الأسئلة داخل الوحدة نفسها.
- لكل نظام حد تكرار مستقل لا يتجاوز 3 مرات للموضع نفسه بين النماذج.

## الملفات الأساسية

- `src/main.jsx`: واجهة الموقع، اختيار النظام والاختبار، المعاينة، التعديل، الطباعة، إنشاء Word وZIP.
- `src/styles.css`: التصميم العربي RTL والواجهة ثلاثية الأبعاد المتجاوبة.
- `generate_project.py`: مولّد الوحدات والأسئلة وملفات Word وتقارير QA.
- `public/ranges/index.json`: فهرس الاختبارات الـ57.
- `public/ranges/lower-01.json` إلى `lower-27.json`: بيانات اختبارات النظام السفلي.
- `public/ranges/upper-01.json` إلى `upper-30.json`: بيانات اختبارات النظام العلوي.
- `QA_REPORT.json`: تقرير الجودة والأعداد والفواصل وقواعد التوليد.
- `supabase/schema.sql`: جدول التعديلات وسياسات القراءة والكتابة للمشرف.

لا يحتاج الموقع إلى رفع ملفات Word ثابتة؛ زر Word ينشئ نسخة حديثة من نموذج محدد، وزر ZIP ينشئ أرشيفًا محدثًا لنموذج واحد أو للاختبار المختار داخل المتصفح. لذلك تظهر تعديلات المشرف في الملفات التي يتم تنزيلها فورًا.

## التشغيل المحلي

يتطلب المشروع Node.js حديثًا وPython 3.12 أو أحدث:

```bash
npm install
npm run dev
```

لبناء نسخة الإنتاج:

```bash
npm run build
npm run preview
```

لإعادة توليد البيانات وملفات Word محليًا:

```bash
. .venv/bin/activate
python generate_project.py
```

ينتج المولّد 1425 نموذجًا، و68,625 سؤالًا، وملفات البيانات المقسمة، وملف QA. ملفات DOCX المحلية الناتجة تُحفظ في `documents/` و`public/documents/`، وهي ملفات توليدية وليست مطلوبة لتشغيل الموقع؛ الموقع ينشئ Word المحدث في المتصفح.

## التعديل المركزي عبر Supabase

1. شغّل محتوى `supabase/schema.sql` مرة واحدة في Supabase SQL Editor.
2. أنشئ مستخدم المشرف من `Authentication > Users`.
3. عطّل التسجيل العام حتى لا ينشئ الزوار حسابات.
4. أضف متغيري البيئة:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. لا تضع مفتاح `service_role` في GitHub أو داخل المتصفح.

بعد تسجيل دخول المشرف، تُحفظ التعديلات في جدول `question_edits` وتظهر لكل الزوار. زر Word وزر ZIP داخل الموقع يستخدمان آخر نسخة معدلة. يمكن استخدام `quran-exam-edits.json` لإعادة توليد الملفات المحلية عند الحاجة.

## النشر

المشروع تطبيق Vite ثابت. أمر البناء:

```bash
npm ci --silent && npm run build
```

ومجلد النشر:

```text
dist/
```

يجب رفع مجلد `public/ranges/` كاملًا، خصوصًا `index.json` وملفات `lower-*.json` و`upper-*.json`. ملفات `.env` والمجلدات التوليدية الكبيرة مستبعدة من Git عبر `.gitignore`.
