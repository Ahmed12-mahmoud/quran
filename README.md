# اختبارات القرآن الكريم

موقع عربي متجاوب لعرض وتنزيل 15 نموذج اختبار شفوي للقرآن الكريم، مع ملفات Word فعلية قابلة للتحرير ومعاينة منظمة داخل المتصفح.

## محتويات المشروع

- `documents/`: ملفات Word الخمسة عشر.
- `public/quran-exams.zip`: أرشيف التنزيل الجماعي الذي يقدمه الموقع.
- `public/documents/`: النسخ التي يقدّمها الموقع للتنزيل.
- `public/models.json`: بيانات البطاقات والمعاينات.
- `src/`: واجهة الموقع وملفات التنسيق.
- `questions_database.json`: قاعدة الأسئلة المركزية المستخدمة في التوليد والتحقق.
- `QA_REPORT.json`: تقرير الفحص البرمجي النهائي.
- `generate_project.py`: سكربت إعادة التوليد من `quran.json`.

## تعديل الأسئلة ومزامنة Word والموقع

المصدر الأساسي للحقيقة هو `questions_database.json`. من داخل الموقع افتح «عرض وتعديل» ثم «تعديل الأسئلة». تُحفظ التعديلات محليًا في المتصفح، ويمكن تصديرها إلى ملف `quran-exam-edits.json`. بعد ذلك تُطبّق التعديلات على قاعدة الأسئلة، ثم يُشغّل `python generate_project.py` لإعادة إنشاء ملفات Word و`public/models.json` معًا. بهذه الطريقة لا يصبح الموقع وملف Word نسختين منفصلتين.

الموقع الثابت على GitHub Pages لا يستطيع الكتابة مباشرة داخل ملفات المستودع أو تعديل DOCX على الخادم. لذلك تتم المزامنة الموثوقة عبر قاعدة JSON المركزية ثم إعادة التوليد. ويمكن استيراد ملف التعديلات من زر «استيراد التعديلات» في الموقع لاستكمال العمل على جهاز آخر.

تم استبعاد سورة الفاتحة من جميع الأسئلة، وأُعيد توزيع مواضع النماذج باستخدام ترتيب عشوائي ثابت داخل أربعة نطاقات واسعة لكل جزء، مع فحص يمنع تكرار الموضع أو بداية الآية المعيارية.

## التشغيل المحلي

يتطلب Node.js حديثًا وPython 3.12 أو أحدث. لتشغيل الموقع:

```bash
npm install
npm run dev
```

ثم افتح العنوان الذي يظهره Vite. ولإنشاء نسخة الإنتاج:

```bash
npm run build
npm run preview
```

## إعادة توليد المستندات

البيانات المصدرية محفوظة في `quran.json`. شغّل:

```bash
. .venv/bin/activate
python generate_project.py
```

ينتج السكربت 15 ملف DOCX، وZIP، وقاعدة الأسئلة، وتقرير QA. يُستخدم التطبيع لإثبات الهوية عند المقارنة فقط؛ أما النص المعروض فيبقى كما ورد في المصدر.

## النشر

الموقع تطبيق Vite ثابت ويمكن نشر مجلد `dist/` على أي استضافة للملفات الثابتة. يشتمل المستودع على `public/manus-routes.json` لخريطة المسارات الخاصة ببيئة Manus. لم يتم ادعاء نشر عام لأن صلاحيات الاستضافة الخارجية غير متوفرة ضمن هذه المهمة.

## المصدر والترخيص

النص العربي من نسخة Uthmani في مشروع Quran JSON، والمصدر الأصلي المعلن هو مشروع Tanzil. يجب إبقاء إشعار المصدر عند إعادة توزيع النصوص. راجع: https://tanzil.net/download/ و https://github.com/risan/quran-json

هذه الحزمة مخصصة لورقة الأسئلة ولا تعرض إجابات نموذجية.

## ربط Supabase وتسجيل دخول المشرف

يوجد كود الربط في `src/lib/supabase.js` ومخطط قاعدة البيانات في `supabase/schema.sql`. شغّل محتوى ملف SQL مرة واحدة في Supabase SQL Editor، ثم أنشئ مستخدم المشرف من `Authentication > Users` وعطّل التسجيل العام. في Render أضف متغيري البيئة `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` باستخدام Project URL وPublishable/anon key، ثم أعد النشر. لا تضع `service_role` في GitHub أو في المتصفح.

بعد تسجيل دخول المشرف من الموقع، تُحفظ تعديلات الأسئلة مركزيًا في جدول `question_edits`. ملفات Word لا تتغير تلقائيًا داخل Static Site؛ عند اعتماد التعديلات صدّر `quran-exam-edits.json`، ضعه بجانب `generate_project.py`، ثم شغّل `python generate_project.py` لإعادة إنشاء Word وبيانات المعاينة.

### تحميل بيانات النماذج

لا يعتمد الموقع على ملف `models.json` واحد كبير. بيانات المعاينة مقسمة إلى `public/ranges/index.json` و30 ملفًا داخل `public/ranges/`، ويحمّل الموقع ملف النطاق الذي اختاره الزائر فقط. يجب رفع مجلد `public/ranges/` كاملًا إلى GitHub.
